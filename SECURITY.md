# Security policy

## Reporting a vulnerability

Open a [private security advisory](https://github.com/earbona23/revtriage/security/advisories/new)
on this repository. Please do not open a public issue for a vulnerability.

I read them. You will get an acknowledgement within 72 hours and an assessment within
seven days. There is no bounty programme — this is a single-maintainer project — but every
report is credited in the advisory unless you ask me not to.

## What counts as a vulnerability here

revtriage is pointed at hostile files by design, so the threat model is inverted from most
tools: **the input is the attacker.** These are in scope, in rough order of severity.

| Class | Why it matters |
|---|---|
| **Anything that executes sample content** | revtriage promises it never runs the file. A path that reaches `eval`, `exec`, `subprocess`, `pickle`, an import of decoded bytes, or a format string under sample control is the most serious bug this project can have. |
| **Escape from parsing into the host** | A crafted archive writing outside the extraction root (zip-slip), a symlink followed, a path traversal in a container member. |
| **Any outbound network call** | The tool is offline. A sample that causes a DNS lookup, an HTTP fetch or an OCSP check has exfiltrated the fact that it is being analysed — and told the operator where the analyst is. |
| **Resource exhaustion from a crafted sample** | A decompression bomb, a pathological regex, or a deobfuscation loop that does not terminate. The budgets in `deobfuscate/pipeline.py` and the archive limits exist to bound this; a bypass is a bug. |
| **Licence verification bypass** | A token that verifies without a valid Ed25519 signature, or an expired one that is accepted. |
| **An indicator printed live** | A URL or host reaching a report undefanged is a click away from being a real request. |

Out of scope: a sample that revtriage scores lower than you would (tune the rules and open
an issue — it is a triage prior, not a verdict on guilt), and missing detections in general.

## What the project does to keep this small

- **Zero runtime dependencies.** `dependencies = []`, verifiable with
  `grep -rE "^(import|from)" src/` — every import is standard library. The supply chain is
  exactly one project.
- **No network code exists.** There is no HTTP client in the package to misuse.
- **The sample is only ever read.** Parsing, pattern matching and decoding over bytes.
- **The tests break it on purpose.** `python scripts/mutation_test.py` introduces fifteen
  real defects one at a time and fails if the suite does not notice.

## Bundled samples

Everything under `fixtures/` is synthetic and inert, generated by `fixtures/build.py`,
which you can read in full. No sample contains a working payload, and every network
indicator points at an RFC 2606 sinkhole (`malware.example`, `example.com`). No binaries
are committed — you build the corpus yourself.
